# ADR-093 — auto-review à barre de preuve vérifiable remplace la revue humaine obligatoire (WIKI auto-promotion)

> Brouillon préparé en lecture seule, hors vault. La ratification = PR signée par l'owner dans `ak125/governance-vault` (commit signé SSH, single write point DEV). L'agent n'écrit JAMAIS au vault et ne s'auto-approuve pas (mainteneur solo).

## Contexte

### La demande owner

Aujourd'hui la promotion d'une fiche WIKI vers le canon (TIER A) est gouvernée par un système qui exige, par défaut, une revue humaine systématique : l'humain est le réviseur par DÉFAUT. La demande est d'inverser ce rapport — **maximiser l'automatisation** pour que l'humain devienne l'**EXCEPTION** (anomalie / escalade), pas le défaut — **sans repli silencieux ni auto-approbation non vérifiable**. On ne SUPPRIME aucun garde-fou : on le **remplace par un gate auto qui EARN** (mérite) le droit d'auto-approuver via une **barre de preuve vérifiable par fiche**. Sous la barre → humain.

### L'invariant et la machinerie actuels (déjà en place)

L'essentiel de la machinerie existe déjà — et, point critique, le **moteur de substance recalibré est déjà câblé** dans `promote.py`, dormant derrière un flag fail-closed OFF. Le gap RÉEL n'est donc PAS une absence de code, mais un **CUTOVER** (flip du flag + baseline-resync) restant owner-gated :

- **Invariant sécurité codé** : `scripts/wiki-generators/auto_review_wiki_proposal.py::compute_auto_promotion` (def l.487) a un **seul** chemin renvoyant `auto_promotion_eligible=True` (l.547), gardé par `is_safety` (défini l.506 ; garde `if is_safety:` l.539 du chemin eligible l.546-549), invariant gravé dans la docstring (l.500). `detect_safety_category(slug, family)` (l.108-119) matche `SAFETY_CATEGORIES` = {freinage, direction, airbag, suspension} (l.91-104).
- **Frontière SEO** : `exportable_seo_allowed` est **TOUJOURS False** (l.588, ADR-033) — le reviewer ne flippe jamais le flag SEO, il est read-only.
- **2e couche promote.py** (479 lignes sur origin/main) : `_scripts/promote.py::evaluate_tier` (l.226) accumule des `reasons`, `tier='A' if not reasons`, **fail-closed** (toute exception → TIER B), exige déjà `truth_level` ∈ {L1, L2} (check l.257, constante `AUTO_PROMOTE_TRUTH_LEVELS` l.59), `confidence_score >= seuil` (défaut `AUTO_PROMOTE_THRESHOLD=1.01` l.58 = no-op, 0 auto-promotion), `>= 2` source kinds distincts (`MIN_DISTINCT_SOURCE_KINDS=2` l.67, check l.285). **Garde sécurité fail-closed en tête (PR #63)** : `_is_safety_proposal` (l.80) ajoute une `reason` dès l.237 → TIER B pour toute famille sécurité. **Garde anti-number-swapping (PR #61)** : `_numeric_review_flags` (l.110) route couple/pression (`block`) vers la revue humaine (l.244-249). Anti-écrasement : `_canon_already_approved` (illisible → True → bloque).
- **3e couche gates** : `_scripts/gates/run_all.py` agrège 5 gates (source/claim/contradiction/risk/confidence), exit 0 ssi tous PASS. `risk_gate.py` câble `gate_safety_unsourced` (`quality-gates.py::gate_safety_unsourced` l.474) qui, depuis PR #63, **n'a plus de constante `SAFETY_FAMILIES` locale** : il importe le single source `safety_families.is_safety_proposal` (l.482-483) couvrant 6 familles {freinage, direction, distribution, electricite-safety, airbag, suspension} + détection par slug — mais ce gate n'inspecte **que** `diagnostic_relations[]` et renvoie `[]` (PASS) si `relations` est vide (early-return, l.487-489).
- **Score legacy non fiable** : `compute-confidence-score.py:105` défaute toute source sans champ `confidence` à `medium`=0.6 au lieu de `high`=1.0 → **déflation OE confirmée** (disque OE = 0.36 alors que le sourcing réel est OE-solide ; cf. MEMORY « score MENT »). Le scalaire pondère structure (sections + liens internes), pas qualité-source. C'est le moteur `legacy` (défaut) du gate de substance.
- **Moteur recalibré DÉJÀ CÂBLÉ, dormant derrière flag** : `_scripts/shadow_score.py` (6-dim, `WEIGHTS` {A:30, B:20, C:20, D:15, E:10, F:5} l.32 ; `TIERS` [(90,S)(80,A)(60,B)(40,C)(0,D)] l.43 ; planchers entity-type-aware via `PROFILES`) **EXISTE sur wiki `origin/main`** ET est **DÉJÀ câblé dans `promote.py`** : `_compute_shadow` (l.191) `import shadow_score as _ss` (l.201) puis `_ss.score(...)` (l.210), consommé par `evaluate_tier` (l.226) sous `PROMOTE_GATE_ENGINE_ENV` (constante l.65, lecture env l.268, défaut `legacy` OFF) comme moteur de substance `adr088_6dim` (tier ∈ `ADR088_PROMOTE_TIERS={A,S}` l.66, check l.272). **Le gap n'est donc PAS « shadow_score n'existe pas / n'est pas câblé » — c'est FAUX** : il existe, il est importé, il est consommé. Le gap réel = le **cutover** (flip `PROMOTE_GATE_ENGINE=adr088_6dim` + baseline-resync, = Phase B) + la **recalibration ADR-091**. ADR-091 (recalibrage du score) est ratifié au vault (PR #325). NB : la docstring de `shadow_score.py` (l.4) dit encore « sans rien remplacer ni câbler à promote.py » — c'est une **dette docstring périmée** (promote.py l.201 l'importe déjà et le consomme), à corriger, pas un fait architectural.

### Limites empiriques découvertes au red-team (3 designs attaqués)

Deux trous structurels, vérifiés dans le code, dominent toute conception :

1. **Trou de classification sécurité (couture — partiellement fermé PR #63).** La qualité « sécurité » dépend d'un appariement **lexical** slug/family par regex fermé. La divergence **intra-wiki** historique (promote vs gate) est **éliminée depuis PR #63** : `gate_safety_unsourced` n'a plus de constante `SAFETY_FAMILIES` locale ; il importe le single source `safety_families.is_safety_proposal` (`quality-gates.py:482-483`) couvrant 6 familles {freinage, direction, distribution, electricite-safety, airbag, suspension} + détection par slug. Vérifié empiriquement sur `origin/main` : `is_safety_proposal({'slug':'courroie-de-distribution'})=True` (désormais capté), idem `disque-de-frein`, `airbag-conducteur`, `amortisseur-avant`=True. **Restent non couverts des deux côtés** (couture résiduelle réelle) : `roulement-de-roue`, `cardan`, `vis-de-roue`/`fixation` = `False`/`None`. **Gap inter-repo résiduel** : le classifieur monorepo `detect_safety_category` garde ses 4 familles {freinage, direction, airbag, suspension} (`SAFETY_CATEGORIES` l.91-105) et renvoie `None` pour `courroie-de-distribution`, là où le wiki le capte. La docstring monorepo (l.89-90) reconnaît « conservative coverage… Extend deliberately » = sous-couverture ASSUMÉE. C'est ce gap résiduel (slugs non couverts + alignement monorepo↔wiki) que la décision L0 ci-dessous prescrit de fermer.
2. **Trou d'exactitude (auto-promo HIGH-HARM désormais bloquée PR #61 ; validation de valeur toujours absente).** AUCUNE couche ne **valide** une **VALEUR numérique** (couple de serrage Nm, cote disque mm, jeu, « remplacer par paire ») — l'exactitude du chiffre n'est jamais vérifiée. Mais depuis PR #61, `promote.py::_numeric_review_flags` (l.110) **route vers la revue humaine** toute fiche portant une valeur HIGH-HARM couple/pression (`CRITICAL_NUMERIC_BLOCK` = Nm/N·m/daNm/bar/kPa/MPa/psi, l.102-104 → `reason` l.244-249 → TIER B), et **flagge** (observabilité, sans bloquer) cotes mm/µm et températures (`CRITICAL_NUMERIC_OBSERVE` l.105-107). L'auto-promotion d'une valeur couple/pression non auto-vérifiable est donc déjà fermée côté wiki. Les checks valident sinon la FORME (présence de champs, absence de filler/marketing, verbe technique, source_kind auto-déclaré). En particulier `shadow_score._dim_A` (l.61) note la **confiance source** et `_dim_F` (l.153-162) est **générique** (`review_status==approved` +0.5 / `lineage_id` +0.3 / `exportable` dict +0.2) — **aucune logique catégorie-sécurité ni vérification de valeur numérique** dans le score. Une valeur FAUSSE mais bien sourcée OE et **non** chiffrée-couple/pression (ex. erreur de transcription, cote mm) reste invisible. La barre prouve la PROVENANCE + la STRUCTURE, jamais l'EXACTITUDE du chiffre ; le verrou exactitude restant (cross-source numérique / plage plausible) est toujours à écrire.

Ces deux trous rendent **inacceptable** toute auto-approbation de contenu à enjeu sécurité tant qu'ils ne sont pas fermés. Cet ADR les traite explicitement (Décision §sécurité + Angles morts).

## Décision

On remplace « revue humaine obligatoire par défaut » par un **gate EARN, défense-en-profondeur, fail-closed, flag-gated, observable, réversible**, qui empile la machinerie EXISTANTE en série et n'ajoute qu'une passe de réfutation/concordance. **Aucun garde-fou n'est supprimé** : chaque condition est un durcissement ADDITIF aux deux points de décision existants (`compute_auto_promotion`, `evaluate_tier`). `tier='A' if not reasons` : toute condition non franchie ajoute une `reason` nommée → TIER B → humain.

### Le gate EARN — couches évaluées en série, chacune fail-closed

- **L0 — Classification sécurité (PÉRIMÈTRE UNIFIÉ ET ÉLARGI).** *État courant (PR #63)* : côté wiki, une **unique** définition canonique existe déjà — `_scripts/safety_families.py::is_safety_proposal` (`SAFETY_FAMILY_LABELS` = 6 familles {freinage, direction, distribution, electricite-safety, airbag, suspension} + `SAFETY_SLUG_PATTERNS`), importée à la fois par `promote.py::_is_safety_proposal` (l.80) et `quality-gates.py::gate_safety_unsourced` (l.482-483). *Ce que cet ADR prescrit en plus* : (a) **aligner le classifieur monorepo** `compute_auto_promotion` / `detect_safety_category` sur ce même single source (aujourd'hui encore ses 4 familles propres), et (b) **étendre l'union** au minimum à : {freinage, direction, airbag, suspension, distribution, electricite-safety, transmission, roulement-de-roue/moyeu, fixation/visserie-de-roue, durite/circuit-de-frein, direction-assistée} — vérifié `roulement-de-roue`/`cardan`/`vis-de-roue` restent `None`/`False` des deux côtés sur `origin/main`. **La classification est fail-CLOSED** : un `None` du classifieur n'est PAS « non-sécurité prouvée » ; c'est « sécurité-INCONNUE » (déjà le cas dans `safety_families` : exception → `True`). Un second détecteur, plus large, scanne **slug + family + body + selection_criteria_top + diagnostic_relations** pour des **tokens sécurité** et des **marqueurs de valeur numérique critique** (couple Nm, cote mm, épaisseur mini, jeu, « par paire », intervalle ; partiellement implémenté par `_numeric_review_flags`, PR #61). Tout hit → famille sécurité → L0 = sécurité → HUMAN. La couture L0 ≠ gate est **observée** (alerte si `family ∈ gate-safety` mais `∉ L0`).
- **L1 — Tri auto_review.** verdict == `REVIEWABLE` (seul chemin `eligible=True`), `source_kind` ⇒ STRONG, les 6 checks structurels PASS, ET — additif — `cross_check_status` est **évalué par sa VALEUR** (aujourd'hui seulement lu présent, l.209) ∈ {SOURCED_OE, WEB_CONFIRMS_RAG} ; RAG_ONLY / NEITHER / absent → échec (fail-closed).
- **L2 — Score recalibré + anti-inflation (FLIP du moteur DÉJÀ câblé).** Bar = `shadow_score.py` (6-dim, planchers entity-type-aware via `PROFILES`) — **PAS** le scalaire `compute-confidence-score` qui déflate l'OE. Le moteur est **déjà importé/consommé par `promote.py`** (`_compute_shadow` l.191 / `import` l.201 / `_ss.score` l.210) ; ce que cet ADR autorise = le **flip du flag `PROMOTE_GATE_ENGINE=adr088_6dim`** (lecture env l.268, défaut `legacy` OFF) pour que ce tier 6-dim devienne le moteur de substance décisionnel. Condition : `shadow_tier ∈ {A, S}` (`ADR088_PROMOTE_TIERS` l.66, check l.272) ET `floors_failed == []`. Dim-A (confiance source, `_dim_A` l.61) pilotée par `source_type` du `_meta/source-catalog.yaml` (oem_* / tecdoc_official / normative_standard → cap high ; brochure / recyclé-RAG → cap medium ; forum / wiki_externe → cap low), pas par le `confidence` auto-déclaré.
- **L3 — Conditions dures promote.py.** `truth_level` ∈ {L1, L2} (check l.257) ; `>= 2` source_refs `kind` distincts **non-recycled** (durcit le check `MIN_DISTINCT_SOURCE_KINDS=2` l.67/l.285 en excluant `kind:recycled`) ; `no_disputed_claims == true` ; `>= N` sources **PRIMAIRES** distinctes (N ≥ 3 non-sécurité ; `source_type` ∈ {oem_manual, oem_workshop, tecdoc_official, normative_standard, parts_feed_certified}) ; les 5 gates `run_all` PASS ; `shadow_tier ∈ {A,S}` (mode `adr088_6dim`) par entity-type non-sécurité, flag `PROMOTE_GATE_ENGINE` flippé **uniquement** sous décision owner (sinon `legacy` + `AUTO_PROMOTE_THRESHOLD=1.01` no-op).
- **L4 — Anti-écrasement.** `_canon_already_approved == False` (illisible → True → bloque).
- **L5 — Réfutation + concordance (NOUVEAU `gates/refutation_gate.py`, enregistré dans la liste `run_all.py` existante, pas de pipeline parallèle).** Passe adversariale qui **cherche à réfuter** : (a) aucun bloc factuel adossé uniquement à `source_ids` préfixés `raw:recycled/rag-knowledge` ; (b) `source_type` du catalogue autorise la confidence déclarée (`confidence_overclaimed`), source existe (`source_slug_unknown`, FK `source_slug → _meta/source-catalog` aujourd'hui enforced par `coverage-map.schema.json` + le workflow CI `cross-repo-source-catalog-gate.yml`) ; (c) `cross_check_status=SOURCED_OE` cohérent avec une réelle diversité de sources primaires ; (d) **CONCORDANCE inter-couches** : L1 STRONG ⟺ L2 dim-A high ⟺ L3 ≥2 kinds ; tout désaccord → `INTER_LAYER_DIVERGENCE` → TIER B. **Le silence du refutateur ne vaut PAS preuve** — il vaut « pas de réfutation trouvée ».

**TIER A auto** ssi **toutes** les couches PASS **et concordent**. Sinon → humain.

### Barre par catégorie

- **Non-sécurité** : barre modérée = L1..L5 ci-dessus, N ≥ 3 sources primaires, `cross_check_status` ∈ {SOURCED_OE, WEB_CONFIRMS_RAG}, `shadow_tier ∈ {A,S}`, 0 dimension RAG_ONLY. Instance de référence : `filtre-a-huile` (1 source recyclée, RAG_ONLY) **échoue** L1+L2+L3+L5.
- **Sécurité** : **barre la plus haute + vérification adversariale auto, et JAMAIS auto-publiée.** Plancher humain **incompressible** : toute fiche sécurité (périmètre L0 unifié, détecteur de valeur compris) → `NEXT_HUMAN_SPOT_CHECK`, quel que soit le score. `disque-de-frein` (family freinage, `reviewed:false`, `diagnostic_safe:false`) reste humain malgré ses 64 sources OE — preuve empirique. L'auto ne fait, au mieux, que **pré-trier « candidat solide »** pour prioriser l'humain.

### Sécurité = barre haute + vérif adversariale auto (jamais « delete le gate »)

1. Invariant `is_safety ⇒ eligible=False ⇒ HUMAN_SPOT_CHECK` (garde `if is_safety:` l.539 du chemin eligible l.546-549, monorepo) **conservé tel quel**, étendu au périmètre L0 unifié. Côté wiki, le miroir est `promote.py::_is_safety_proposal` (l.80, appelé l.237) déjà actif (PR #63).
2. `gate_safety_unsourced` (`quality-gates.py:474`) **conservé** — il délègue désormais au single source `safety_families.is_safety_proposal` (l.482-483, 6 familles + slug ; plus de constante `SAFETY_FAMILIES` locale), MAIS sa portée est encore à étendre : il ne doit plus PASS quand `diagnostic_relations` est vide (early-return l.487-489) pour une fiche sécurité portant des faits dans `selection_criteria_top`/`body` (fermeture du trou d'early-return sur `relations` vide).
3. **Verrou exactitude** : toute fiche portant une valeur chiffrée critique (couple / cote / jeu / épaisseur mini / intervalle / « par paire ») est **catégoriquement exclue de l'auto-approve** tant qu'aucune vérification de VALEUR n'existe (cross-source numérique ou plage plausible) → HUMAN incompressible. Rappel : le score 6-dim (`_dim_A` l.61, `_dim_F` l.153-162) ne valide AUCUNE valeur numérique.
4. La **VRAIE barrière sécurité « une fiche sécurité ne s'auto-promeut pas »** repose sur `promote.py::_is_safety_proposal` (l.80, appelé en tête d'`evaluate_tier` l.237 → TIER B avant toute substance, PR #63) + `gate_safety_unsourced` (`quality-gates.py:474`) composé par les 5 gates atomiques **en amont** de `evaluate_tier` (l.226), tous deux délégant au single source `safety_families.is_safety_proposal`, + le flag de substance OFF fail-closed (défaut `legacy`, `AUTO_PROMOTE_THRESHOLD=1.01` no-op) — **PAS** `_dim_F`. Le score recalibré (ADR-091 / mode `adr088_6dim`) est une **CONDITION NÉCESSAIRE, JAMAIS SUFFISANTE** pour la sécurité ; et l'auto-approve sécurité reste **interdit** quel que soit le tier. **Aucune auto-promotion sécurité sur un score non recalibré** — voir Plan de mise en œuvre (dépendance dure).

### Humain = exception

L'humain est sollicité uniquement sur : (1) toute famille sécurité (périmètre L0 unifié + détecteur de valeur) ; (2) `INTER_LAYER_DIVERGENCE` ; (3) tout gate `run_all` ≠ PASS ; (4) `floors_failed` non vide ; (5) `cross_check_status` ∈ {RAG_ONLY, NEITHER} ou dimension RAG_ONLY ; (6) `_canon_already_approved` True ou illisible ; (7) réfutation réussie ; (8) toute exception / champ manquant (fail-closed) ; (9) tout flip `exportable.seo` — TOUJOURS humain (ADR-033). Le reste (non-sécurité, barre franchie, refutateur silencieux, couches concordantes) → TIER A auto.

## Conséquences

### Ce qui s'automatise

- Les fiches **non-sécurité** OE-solides, multi-sources primaires, à couches concordantes, sans valeur chiffrée critique, s'auto-promeuvent en TIER A — l'humain ne les voit plus.
- La revue humaine systématique cesse d'être le défaut sur ce périmètre ; elle devient ciblée sur les anomalies.

### Ce qui reste (feu vert owner / humain)

- **Toute la sécurité** reste humaine (plancher incompressible). Aucun score ne l'ouvre.
- Le **flip `exportable.seo`** reste 100 % humain (ADR-033).
- L'**activation du flag** (`PROMOTE_GATE_ENGINE=adr088_6dim`) et le passage report-only → enforce restent un **GO owner explicite** (pas d'auto-escalade après un seul « fais-le »). Le moteur est déjà câblé mais dormant ; seul le flip change le comportement.
- La **ratification de cet ADR** = PR signée par l'owner au vault.

### Risque résiduel

1. Planchers `shadow_score` (`PROFILES`) à **calibrer** empiriquement (trop bas → contenu faible auto-approuvé ; trop haut → 0 gain) — mitigé par phase shadow report-only old-vs-new AVANT cutover, qui est déjà tracée puisque `_compute_shadow` calcule le tier 6-dim « à côté » dans les deux modes.
2. `source_type` dépend de l'exactitude déclarative du `source-catalog.yaml` ; mis-catalogue (RAG étiqueté oem_*) gonflerait dim-A — partiellement mitigé par L5 (préfixes `raw:recycled` vérifiés indépendamment + FK `source_slug` enforced par `coverage-map.schema.json` + CI `cross-repo-source-catalog-gate.yml`) + audit catalogue, **pas totalement clos**.
3. `cross_check_status` est producteur-déclaré ; L5 le recoupe avec la diversité mais ne prouve pas la provenance OE depuis le frontmatter seul (pas de re-fetch sémantique).
4. L5 vérifie l'EXISTENCE/TYPE/COHÉRENCE des sources, **jamais le CONTENU sémantique** — une affirmation fausse bien sourcée n'est rattrapée que par le verrou exactitude (sécurité) + N≥3 + report-only (non-sécurité). La vérification sémantique réelle (fetch + NLI) est **hors scope V1**.
5. Deux moteurs (auto_review monorepo + promote wiki) doivent rester synchronisés sur le périmètre sécurité et la barre → risque de drift ; mitigé par périmètre + seuils centralisés/documentés dans l'ADR.
6. Le gap n'est PAS l'absence de `shadow_score.py` (il existe sur wiki `origin/main` et est déjà câblé dans `promote.py`) mais le **cutover** : flip du flag `PROMOTE_GATE_ENGINE` + baseline-resync (Phase B) + recalibration ADR-091. Tant que ces étapes ne sont pas franchies sous GO owner, le mode reste `legacy` (no-op), donc 0 régression. La dette docstring de `shadow_score.py` (l.4 « sans câbler à promote.py ») doit être corrigée pour refléter le câblage réel.

## Alternatives rejetées

- **Supprimer le gate / passer la sécurité en auto sur le score.** REJETÉ — bricolage interdit, suppression de garde-fou, viole « no silent fallback » et l'invariant sécurité. On ne supprime jamais un garde-fou : on le remplace par une porte auto qui MÉRITE le droit.
- **S'appuyer sur le scalaire `compute-confidence-score` comme barre.** REJETÉ — déflation OE prouvée (disque 0.36 ; `compute-confidence-score.py:105` défaut medium=0.6). On flippe le moteur `shadow_score` (ADR-091, mode `adr088_6dim`) **déjà câblé** à la place ; on **n'édite pas** la formule scalaire en place (briserait le mode `--check` des fiches existantes).
- **Garder la sécurité sur le classifieur lexical fermé actuel.** REJETÉ — trou de classification prouvé (distribution / roulement / cardan / vis-de-roue = `None`). On unifie + élargit + fail-close.
- **Présenter `refutation_gate` comme vérification de faits.** REJETÉ — c'est de la cohérence-source structurelle ; ne pas survendre. Les valeurs numériques sécurité restent humaines tant qu'aucune vérif de valeur n'existe.
- **Créer un nouveau scoreur / pipeline parallèle.** REJETÉ — on étend la machinerie existante (deux points d'extension + un gate dans `run_all` + le flip d'un moteur déjà câblé), conformément à « prefer extension over creation ».

## Garde-fous

- **No-silent-fallback.** Fail-closed intégral : toute exception / doute / champ manquant / illisible → `reason` → TIER B ; score indéterminable → 0.0 / `shadow_tier` absent → blocage → humain ; canon illisible → bloque. Le silence du refutateur ne vaut pas preuve. La classification `None` ne vaut pas « non-sécurité » → sécurité-inconnue → humain. Flag OFF (`PROMOTE_GATE_ENGINE=legacy`, défaut) = aucune dégradation silencieuse (`AUTO_PROMOTE_THRESHOLD` reste 1.01 no-op).
- **Observable.** Chaque décision trace `promotion_evidence` (gate_status + score + promoter) + `blocking_reasons` + `auto_promotion_reason`/`next_action` + breakdown 6-dim (`shadow_dims`, déjà attaché par `_compute_shadow`) + `floors_failed` + verdict réfutation + `INTER_LAYER_DIVERGENCE`. Comparaison shadow old-vs-new (déjà calculée dans les deux modes) pour mesurer le taux d'auto-approbation et l'écart de recalibrage AVANT cutover. Pas de canary externe — réutilise la trace existante.
- **Réversible.** Additif pur : aucune ligne retirée des gardes actuels ; les conditions sont des `reasons` supplémentaires + une condition avant le seul `eligible=True`.
