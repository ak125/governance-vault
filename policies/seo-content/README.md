# `policies/seo-content/`

OPA Rego policies governing SEO content writes in the AutoMecanik monorepo.

## Files

| Path | Role |
|---|---|
| `h1-write.rego` | Authorization policy for H1 field writes (PR-V) |
| `h1-write_test.rego` | Unit tests (22 cases : allow/deny per source_kind) |

## Build artefacts

Generated by `.github/workflows/opa-policy-build.yml` and committed to
`dist/policies/` for consumption by the NestJS gateway (PR-C, monorepo).

| Path | Role |
|---|---|
| `../../dist/policies/h1-write.bundle.tar.gz` | OPA WASM bundle (full) |
| `../../dist/policies/h1-write.wasm` | Extracted WASM module |

## Local rebuild

```bash
# Run tests
opa test policies/seo-content/ -v

# Build WASM bundle
opa build \
  -t wasm \
  -e seo/content/h1/write/allow \
  -e seo/content/h1/write/deny \
  -o dist/policies/h1-write.bundle.tar.gz \
  policies/seo-content/h1-write.rego

# Extract WASM module
tar -xzf dist/policies/h1-write.bundle.tar.gz /policy.wasm
mv policy.wasm dist/policies/h1-write.wasm
```

OPA version pinned : **0.69.0** (verified reproducible WASM SHA-256).

## Source of authority (NOT this repo)

The "who is allowed to write what" decisions are declared in the monorepo
canon registry :

```
ak125/nestjs-remix-monorepo:.spec/00-canon/repository-registry/seo-field-authority.yaml
```

PR-B #535. This Rego policy *applies* those decisions at runtime ; it does
not invent authority. Any change to authoritative/denied writers must originate
in the YAML canon.

## Consumed by

- **PR-C** (monorepo, future) : `backend/src/modules/seo/governance/opa-policy-engine.service.ts`
  loads the WASM bundle in-memory and evaluates synchronously (target < 1ms) on
  every H1 write attempt via the `@SeoFieldGuard('h1', 'write')` decorator.
- **PR-E** (monorepo, future) : recovery rollout worker submits writes flagged
  `legacy_recovery` with `evidence_tier` in `exact_match_*` (gate evaluated by
  this policy).
